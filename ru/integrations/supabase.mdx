На любом тарифе Webza вы можете сделать сгенерированные приложения с поддержкой базы данных, прикрепив свой проект Supabase. Ваши приложения получают реляционные таблицы Postgres, аутентификацию, хранилище и безопасность на уровне строк (RLS). ИИ определяет таблицы и потоки аутентификации за вас по ходу сборки.

<Note>
  Подключения баз данных недоступны для проектов тем WordPress или Shopify.
</Note>

## Вы владеете базой данных

Webza использует модель принеси-свою-базу-данных. Вы предоставляете проект Supabase, и сгенерированные приложения общаются с ним через клиент `@supabase/supabase-js`. Webza никогда не создает, не размещает, не владеет и не выставляет счета за вашу базу данных.

- Вы храните библиотеку своих подключений Supabase и прикрепляете одно к каждому проекту.
- Webza создает выделенную схему в вашей базе данных для каждого проекта и строит таблицы там.
- Webza никогда не удаляет ваши данные, даже когда вы удаляете проект.

## Как это работает

<Steps>
  <Step title="Добавьте подключение">
    Сохраните одно или несколько подключений Supabase на странице **Базы данных** в боковой панели.
  </Step>
  <Step title="Выберите его для проекта">
    Выберите подключение из селектора **База данных** при создании проекта. Оно подключается с первой сборки.
  </Step>
  <Step title="Дайте ИИ собрать">
    Webza создает схему Postgres в вашем проекте Supabase с включенным RLS. ИИ добавляет в нее таблицы по ходу сборки вашего приложения.
  </Step>
</Steps>

## Добавление подключения Supabase

Откройте **Базы данных** из боковой панели и нажмите **Добавить подключение**. Каждое подключение хранит имя и доступ к одному проекту Supabase. Вы можете сохранить до 20 подключений и повторно использовать их между проектами.

Методы, которые вы видите, зависят от того, что включено для вашего аккаунта. Если доступен только один метод, **Добавить подключение** открывает его напрямую.

| Метод | Что нужно | Область доступа |
| --- | --- | --- |
| **Подключиться через Supabase** | Ваши данные входа в Supabase | Каждый проект в организации, которую вы авторизуете |
| **Токен доступа** | Токен доступа с областью проекта | Только выбранный вами проект |
| **Вручную** | URI Session pooler, пароль базы данных и публичный ключ | Только этот проект |

<Tabs>
  <Tab title="Подключиться через Supabase">
    <Steps>
      <Step title="Начните вход">
        На странице **Базы данных** нажмите **Добавить подключение** и выберите **Подключиться через Supabase**.
      </Step>
      <Step title="Авторизуйте Webza">
        Просмотрите разрешения на экране согласия Supabase и авторизуйте организацию, в которой находится ваш проект. Supabase указывает **База данных** как чтение и запись, потому что запись включает чтение.
      </Step>
      <Step title="Выберите проект">
        Выберите активный проект и сохраните подключение.
      </Step>
    </Steps>

    <Warning>
      Supabase предоставляет доступ на уровне организации, поэтому вы авторизуете каждый проект в выбранной организации. Webza работает только в выбранном вами проекте. Чтобы ограничить доступ одним проектом, используйте вместо этого токен доступа.
    </Warning>

    Сеансы OAuth обновляются автоматически, так что вам не нужно входить снова, пока доступ остается предоставленным.
  </Tab>
  <Tab title="Токен доступа">
    <Steps>
      <Step title="Создайте токен в Supabase">
        В Supabase откройте **Account → Access Tokens** и создайте токен. Выберите **Project access**, укажите только проект, который хотите подключить, и задайте срок действия.
      </Step>
      <Step title="Настройте разрешения">
        Предоставьте точно эти разрешения:

        - **База данных**: Read-write
        - **API-ключи**: Read
        - **Проекты** (account-wide): Read
      </Step>
      <Step title="Сохраните в Webza">
        Откройте **Базы данных → Добавить подключение → Токен доступа**, вставьте токен и нажмите **Продолжить**. Выберите ваш проект и сохраните. Webza сама получит URL проекта и публичный ключ.
      </Step>
    </Steps>

    <Note>
      Принимаются только токены с областью проекта, начинающиеся с `sbp_fc`. Устаревшие полноаккаунтные токены отклоняются. Приостановленные или недоступные проекты нельзя выбрать.
    </Note>
  </Tab>
  <Tab title="Вручную">
    <Steps>
      <Step title="Создайте проект Supabase">
        Войдите в [Supabase Dashboard](https://supabase.com/dashboard) и создайте проект. Бесплатного уровня достаточно для начала.
      </Step>
      <Step title="Скопируйте публичный ключ">
        Откройте **Project Settings → API Keys** и скопируйте публичный ключ (`sb_publishable_…`). В старых проектах может отображаться устаревший ключ `anon` в разделе **Project Settings → API**, который тоже работает.
      </Step>
      <Step title="Скопируйте URI Session pooler">
        Нажмите **Connect** вверху вашего проекта Supabase, выберите **Session pooler** и тип **URI**, затем скопируйте строку подключения. Сохраните `[YOUR-PASSWORD]` в ней.

        ```text
        postgresql://postgres.abcdefgh:[YOUR-PASSWORD]@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres
        ```
      </Step>
      <Step title="Сохраните в Webza">
        Откройте **Базы данных → Добавить подключение → Вручную** и заполните:

        - **Название подключения**: любое имя, по которому вы его узнаете.
        - **Строка подключения**: URI Session pooler. Она должна начинаться с `postgres://` или `postgresql://`. Не вставляйте команду `psql`.
        - **Пароль базы данных**: ваш пароль базы данных. Webza шифрует его и вставляет вместо `[YOUR-PASSWORD]`.
        - **Публичный ключ**: скопированный ключ.

        **URL Supabase** заполняется автоматически из строки подключения. Он должен начинаться с `https://`.
      </Step>
      <Step title="Проверьте подключение">
        Нажмите **Проверить подключение**. Оно проверяет доступ к базе данных и публичный ключ отдельно.
      </Step>
    </Steps>

    При редактировании ручного подключения позже, оставление строки подключения или публичного ключа пустым сохраняет сохраненное значение.
  </Tab>
</Tabs>

### Отключение подтверждения по email

Чтобы регистрация в ваших сгенерированных приложениях работала мгновенно, отключите подтверждение по email в Supabase. Перейдите в **Authentication → Sign In / Providers → Email**, выключите **Confirm email** и сохраните.

<Warning>
  Если вы не настроили SMTP в вашем проекте Supabase, оставление подтверждения включенным означает, что регистрация никогда не возвращает активную сессию, и вход молча завершается неудачей.
</Warning>

## Прикрепление базы данных к проекту

На странице создания откройте всплывающее окно **Настроить** и выберите подключение из селектора **База данных**. Селектор появляется только после сохранения хотя бы одного подключения. Оставьте на **Нет базы данных** для статического сайта.

Чтобы прикрепить, переключить или отсоединить базу данных позже, перейдите в **Настройки → База данных** в проекте.

- Переключение подключений никогда не удаляет схему. Старая схема остается в базе данных, где была создана.
- Вы можете отсоединить базу данных в любое время.
- Дублирование проекта не копирует подключение к базе данных.

## Режимы доступа к таблицам

Каждая таблица, созданная ИИ, использует один из трех режимов доступа. Режим определяет, какие политики RLS Webza запишет для вас, поэтому это самый важный выбор безопасности в приложении с поддержкой базы данных.

| Режим | Кто может писать | Кто может читать | Используйте для |
| --- | --- | --- | --- |
| `public` | Кто угодно | Кто угодно | Гостевые книги, комментарии, публичные отзывы |
| `private` | Авторизованный владелец строки | Авторизованный владелец строки | Задачи, заметки, профили, другие персональные данные |
| `submit` | Кто угодно | Никто из приложения | Контактные формы, запросы, списки ожидания, подписки на рассылку |

<Warning>
  Никогда не используйте `public` для отправки форм. Публичный ключ по дизайну включен в JavaScript вашего сайта, так что кто угодно может читать и удалять каждую строку в таблице `public`. Используйте `submit` для всего, что посетители отправляют вам конфиденциально.
</Warning>

Таблица `submit` позволяет посетителям вставлять строки, но их нельзя прочитать, обновить или удалить из браузера. Ваше приложение отправляет форму и показывает сообщение об успехе. Читайте отправки в панели управления Supabase.

Вы можете сказать ИИ, какой режим использовать, в вашем запросе, например: "Храните сообщения контактной формы в таблице submit."

### Изменение режима таблицы

Попросите ИИ переопределить существующую таблицу с другим режимом. Webza перестроит политики таблицы соответственно и сохранит ее данные.

<Warning>
  Переключение таблицы `public` или `submit` на `private` скрывает существующие строки. У этих строк нет владельца, так что ни один пользователь не может видеть их в приложении. Данные все еще находятся в вашей панели управления Supabase. Если строки важны, назначьте владельцев или экспортируйте их перед переключением.
</Warning>

### Управляемые столбцы

Каждая таблица автоматически получает столбцы `id` и `created_at`. Таблицы `private` также получают столбец `user_id`. Не определяйте эти столбцы сами.

## Что получает ваше приложение

- **Реляционный Postgres**: настоящие таблицы, внешние ключи и SQL-запросы.
- **Безопасность на уровне строк**: политики доступа к каждой строке, принудительно применяемые Postgres.
- **Аутентификация и хранилище**: ваше приложение может использовать Supabase Auth (email и пароль или вход через провайдера) и Storage buckets. Настраивайте провайдеров Auth и Storage buckets в своей панели управления Supabase.

Каждый проект получает свою схему с именем `proj_`, за которым следует ID проекта без дефисов. Например, проект с ID `3f0c1a2b-…` использует `proj_3f0c1a2b…`.

Сгенерированные приложения получают только URL проекта, публичный ключ и имя схемы. Токены доступа и строки подключения шифруются и никогда не попадают в браузер.

<Info>
  Удаление проекта, отсоединение базы данных или переключение подключений никогда не удаляет схему или данные проекта. Чтобы освободить место, удалите схему `proj_…` самостоятельно в панели управления Supabase.
</Info>

## Управление доступом

- Один токен доступа или вход в Supabase может поддерживать несколько подключений. Переподключение входа в Supabase исправляет каждое подключение, созданное из него.
- Новый токен доступа применяется только к подключению, которое вы редактируете. Вставьте новый токен в каждое подключение, которое использовало старый.
- Вы можете хранить до 10 токенов и входов.

Удаление подключения в Webza не отзывает доступ в Supabase. Чтобы отозвать доступ:

- **Подключиться через Supabase**: удалите Webza в разделе **Settings → OAuth Apps → Authorized apps** вашей организации.
- **Токен доступа**: удалите токен в разделе **Account → Access Tokens**.

Когда доступ отозван или токен истекает, подключение показывает **Переподключить** на странице **Базы данных**, и сборки сообщают, что доступ отозван. Переподключение исправляет подключение на месте, так что прикрепленные проекты сохраняют свои схемы.

## Устранение неполадок

<AccordionGroup>
  <Accordion title="Проверка подключения не удалась">
    - Для ручных подключений используйте URI Session pooler из раздела **Connect**, сохраните `[YOUR-PASSWORD]`, и введите пароль в поле **Пароль базы данных**.
    - Если публичный ключ отклонен, скопируйте его снова из того же проекта Supabase.
    - Убедитесь, что проект Supabase активен, а не приостановлен.
    - Если подключение показывает **Переподключить**, замените токен или снова авторизуйте Webza.
  </Accordion>

  <Accordion title="Мое приложение не показывает отправки форм">
    Это ожидаемое поведение для таблиц `submit`. Они доступны только для записи из браузера, так что отправки никогда не появляются в приложении. Читайте их в панели управления Supabase. Если ваше приложение, кажется, показывает отправки, оно отображает примеры заполнителей.
  </Accordion>

  <Accordion title="Мое приложение не может читать данные">
    - Подтвердите, что подключение прикреплено в **Настройки → База данных** проекта.
    - Подтвердите, что публичный ключ проходит **Проверку подключения**.
    - Проверьте режим доступа таблицы. RLS отклоняет доступ, если политика не разрешает его.
  </Accordion>

  <Accordion title="Регистрация работает, но вход не удается">
    Отключите **Confirm email** в вашем проекте Supabase или настройте SMTP. См. [Отключение подтверждения по email](#отключение-подтверждения-по-email).
  </Accordion>

  <Accordion title="Мои изменения схемы в Supabase были отменены">
    Webza управляет тем, какие схемы открыты для API Supabase. Редактирование **Exposed schemas** в панели управления Supabase переопределяется настройками Webza.
  </Accordion>
</AccordionGroup>
