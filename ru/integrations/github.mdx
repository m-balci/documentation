На любом тарифе Webza вы можете подключить свой аккаунт GitHub, чтобы Webza отправляла исходный код проекта в репозиторий вашего аккаунта после каждой успешной сборки. Код находится под вашим контролем, и вам никогда не нужно покидать Webza, чтобы поддерживать его в актуальном состоянии.

<Note>
  Интеграция GitHub недоступна для проектов тем WordPress или Shopify.
</Note>

## Как это работает

<Steps>
  <Step title="Подключите свой аккаунт GitHub">
    Установите приложение Webza GitHub на свой аккаунт или организацию и свяжите его в Webza.
  </Step>
  <Step title="Выберите аккаунт для проекта">
    Выберите подключение GitHub при создании проекта. Webza создает для него новый приватный репозиторий.
  </Step>
  <Step title="Соберите">
    После каждой успешной сборки ИИ отправляет исходный код проекта с автоматически сгенерированным сообщением коммита.
  </Step>
</Steps>

<Info>
  Webza отправляет данные только в ваш репозиторий. Она никогда не клонирует, не пуллит и не собирает из содержимого репозитория. Репозиторий, это вывод, а не вход.
</Info>

## Подключение аккаунта GitHub

<Steps>
  <Step title="Откройте GitHub в боковой панели">
    Нажмите **GitHub** в боковой панели, затем нажмите **Подключить GitHub**.
  </Step>
  <Step title="Установите приложение Webza">
    GitHub попросит вас установить приложение Webza. Выберите, предоставлять ли доступ ко всем репозиториям или только к выбранным.
  </Step>
  <Step title="Вернитесь в Webza">
    Вас перенаправят обратно в Webza с сохраненным подключением.
  </Step>
</Steps>

Вы можете связать несколько личных аккаунтов или организаций, до 20 подключений.

## Подключение репозитория к проекту

При создании проекта нажмите **Настроить** на панели запросов, затем выберите **Интеграции** и выберите подключение GitHub. Webza создает репозиторий автоматически.

Для существующего проекта перейдите в **Настройки → Общие** и найдите раздел **Репозиторий GitHub**. Оттуда вы можете:

- Создать новый приватный репозиторий.
- Прикрепить существующий репозиторий, введя владельца и имя репозитория.
- Переключиться на другой репозиторий или отвязать его.
- Включить или выключить **Автоматическую отправку**.

<Warning>
  Существующий репозиторий должен быть пустым. Прикрепление репозитория, который уже содержит код, завершится ошибкой "That repository already contains code", потому что иначе Webza перезаписала бы работу, которую не видит.
</Warning>

Дублирование проекта не копирует подключение GitHub. Совместное использование одного репозитория между проектами позволило бы одному перезаписать файлы другого, поэтому каждому проекту нужна своя связь.

## Отправка по запросу

Выключение **Автоматической отправки** не означает, что вам придется отправлять вручную. Попросите ИИ в чате проекта, например "Отправь это в GitHub", и он выполнит разовую отправку независимо от переключателя.

<Tip>
  Выключите автоматическую отправку, если хотите просматривать изменения перед каждым коммитом, а затем попросите ИИ отправить, когда будете готовы.
</Tip>

## Что отправляется

Webza отправляет исходный код проекта, который разработчик хотел бы прочитать, а не полную копию рабочего пространства. Зависимости, вывод сборки и все, что похоже на учетные данные, исключаются, так что секреты не публикуются в вашем репозитории.

## Редактирование репозитория вне Webza

Отправки никогда не форсируются. Если кто-то делает коммит в репозиторий вне Webza, следующая отправка пропускается, чтобы ваши изменения не были потеряны.

<Warning>
  После этого ваш репозиторий и проект Webza расходятся. Webza не сливает внешние изменения обратно в проект, и дальнейшие отправки в эту ветку пропускаются.
</Warning>

## Безопасность

- Ваши токены GitHub хранятся в зашифрованном виде и никогда не включаются в ответы API.
- Каждая отправка использует свежий токен, который действует один час и работает только для этого одного репозитория.

## Статус подключения

Каждое подключение на странице **GitHub** показывает один из трех состояний:

| Статус | Что означает | Что делать |
| --- | --- | --- |
| **Активно** | Работает нормально | Ничего |
| **Требуется переподключение** | Вы удалили авторизацию Webza, но оставили приложение установленным. Отправки по-прежнему работают, но вы не можете связать репозиторий с новым проектом. | Нажмите **Переподключить** |
| **Отозвано** | Приложение было удалено или приостановлено. Ничего не работает. | Нажмите **Переподключить** |

## Удаление доступа

Отвяжите репозиторий от проекта в **Настройки → Общие**. Ничего не удаляется из вашего аккаунта GitHub.

Чтобы полностью отозвать доступ Webza, удалите приложение Webza из настроек GitHub. Ваши репозитории и их содержимое остаются в вашем аккаунте.

## Устранение неполадок

<AccordionGroup>
  <Accordion title="Отправки остановились">
    - Кто-то мог сделать коммит в репозиторий вне Webza. Отправки пропускаются, чтобы защитить эти изменения.
    - Приложение Webza могло быть удалено из вашего аккаунта GitHub. Проверьте статус подключения на странице **GitHub** и переподключитесь.
    - Проверьте, что **Автоматическая отправка** включена в **Настройки → Общие** проекта.
  </Accordion>

  <Accordion title="Я не могу прикрепить существующий репозиторий">
    Репозиторий должен быть пустым. Создайте новый пустой репозиторий на GitHub или позвольте Webza создать его за вас.
  </Accordion>

  <Accordion title="Webza не видит мой репозиторий">
    Если вы предоставили доступ только к выбранным репозиториям, добавьте репозиторий в список доступа приложения Webza в настройках GitHub.
  </Accordion>

  <Accordion title="Подключение организации перестало работать">
    Если авторизация для подключения организации была удалена, Webza может не обнаружить это сразу. Вы увидите это при следующей попытке связать репозиторий. Переподключитесь со страницы **GitHub**.
  </Accordion>
</AccordionGroup>
