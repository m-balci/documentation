すべてのWebzaプランで、GitHubアカウントを接続して、各ビルド後にWebzaがプロジェクトのソースコードをアカウント内のリポジトリにプッシュできるようにできます。コードはあなたの管理下にあり、最新の状態を保つためにWebzaを離れる必要はありません。

<Note>
  GitHub連携は、WordPressまたはShopifyテーマプロジェクトでは利用できません。
</Note>

## 仕組み

<Steps>
  <Step title="GitHubアカウントを接続する">
    Webza GitHub Appをアカウントまたは組織にインストールし、Webzaでリンクします。
  </Step>
  <Step title="プロジェクト用のアカウントを選ぶ">
    プロジェクト作成時にGitHub接続を選びます。Webzaがそれ用の新しいプライベートリポジトリを作成します。
  </Step>
  <Step title="ビルドする">
    各ビルドが成功するたびに、AIが生成されたコミットメッセージ付きでプロジェクトソースをプッシュします。
  </Step>
</Steps>

<Info>
  Webzaはリポジトリへのプッシュのみを行います。リポジトリの内容をクローン、プル、またはビルドすることはありません。リポジトリは出力であり、入力ではありません。
</Info>

## GitHubアカウントを接続する

<Steps>
  <Step title="サイドバーでGitHubを開く">
    サイドバーで**GitHub**をクリックし、次に**GitHubを接続**をクリックします。
  </Step>
  <Step title="Webzaアプリをインストールする">
    GitHubがWebzaアプリのインストールを求めます。すべてのリポジトリへのアクセスを許可するか、選択されたリポジトリのみにするかを選びます。
  </Step>
  <Step title="Webzaに戻る">
    接続が保存された状態でWebzaに戻されます。
  </Step>
</Steps>

複数の個人アカウントまたは組織をリンクでき、最大20の接続まで可能です。

## リポジトリをプロジェクトに接続する

プロジェクト作成時に、ダッシュボードのプロンプトボックスで**カスタマイズ**をクリックし、**連携**を選択してGitHub接続を選びます。Webzaが自動的にリポジトリを作成します。

既存のプロジェクトの場合、**設定 → 一般**に移動し、**GitHubリポジトリ**セクションを探します。そこから以下が可能です。

- 新しいプライベートリポジトリを作成する。
- 所有者とリポジトリ名を入力して既存のリポジトリをアタッチする。
- 別のリポジトリに切り替えるか、リンクを解除する。
- **自動プッシュ**をオンまたはオフにする。

<Warning>
  既存のリポジトリは空である必要があります。すでにコードが含まれているリポジトリをアタッチすると、「That repository already contains code」エラーになります。Webzaが確認できない作業を上書きしてしまうためです。
</Warning>

プロジェクトを複製してもGitHub接続はコピーされません。1つのリポジトリを複数のプロジェクトで共有すると、一方が他方のファイルを上書きする可能性があるため、各プロジェクトには独自のリンクが必要です。

## リクエスト時にプッシュする

**自動プッシュ**をオフにしても、手動でプッシュする必要があるわけではありません。プロジェクトチャットでAIに依頼すれば、例えば「GitHubにプッシュして」と言うだけで、トグルの状態に関わらずワンオフのプッシュが実行されます。

<Tip>
  各コミットが反映される前に変更を確認したい場合は自動プッシュをオフにして、準備ができたらAIにプッシュを依頼してください。
</Tip>

## プッシュされる内容

Webzaがプッシュするのは、開発者が読みたいプロジェクトソースであり、ワークスペースの完全なコピーではありません。依存関係、ビルド出力、および認証情報と見られるものは除外されるため、シークレットがリポジトリに公開されることはありません。

## Webza外でリポジトリを編集する

プッシュは強制されません。Webza外で誰かがリポジトリにコミットした場合、次のプッシュはスキップされ、変更が失われないように保護されます。

<Warning>
  その後、リポジトリとWebzaプロジェクトは同期しなくなります。Webzaは外部の変更をプロジェクトにマージ戻しせず、そのブランチへの今後のプッシュもスキップされます。
</Warning>

## セキュリティ

- GitHubトークンは暗号化されて保存され、APIレスポンスには含まれません。
- 各プッシュは、1時間のみ有効でその1つのリポジトリでのみ機能する新鮮なトークンを使用します。

## 接続ステータス

**GitHub**ページの各接続は、3つの状態のいずれかを示します。

| ステータス | 意味 | 対処方法 |
| --- | --- | --- |
| **アクティブ** | 正常に動作中 | 何もする必要はありません |
| **再接続が必要** | Webzaの認可を削除しましたが、アプリはインストールされたままです。プッシュは引き続き機能しますが、新しいプロジェクトにリポジトリをリンクできません。 | **再接続**をクリックしてください |
| **取り消し済み** | アプリがアンインストールまたは一時停止されました。何も機能しません。 | **再接続**をクリックしてください |

## アクセスを削除する

プロジェクトからのリポジトリのリンク解除は、**設定 → 一般**で行います。GitHubアカウントから何も削除されません。

Webzaへのアクセスを完全に取り消すには、GitHub設定からWebzaアプリをアンインストールしてください。リポジトリとその内容はアカウントに残ります。

## トラブルシューティング

<AccordionGroup>
  <Accordion title="プッシュが停止した">
    - Webza外で誰かがリポジトリにコミットした可能性があります。変更を保護するため、プッシュがスキップされています。
    - WebzaアプリがGitHubアカウントからアンインストールされた可能性があります。**GitHub**ページで接続ステータスを確認し、再接続してください。
    - プロジェクトの**設定 → 一般**で**自動プッシュ**がオンになっていることを確認してください。
  </Accordion>

  <Accordion title="既存のリポジトリをアタッチできない">
    リポジトリは空である必要があります。GitHubで新しい空のリポジトリを作成するか、Webzaに作成させてください。
  </Accordion>

  <Accordion title="Webzaがリポジトリを認識しない">
    選択されたリポジトリのみへのアクセスを許可した場合、GitHub設定でWebzaアプリのアクセスリストにリポジトリを追加してください。
  </Accordion>

  <Accordion title="組織接続が停止した">
    組織接続の認可が削除された場合、Webzaはすぐに検出しないことがあります。次にリポジトリをリンクしようとしたときに気づきます。**GitHub**ページから再接続してください。
  </Accordion>
</AccordionGroup>
