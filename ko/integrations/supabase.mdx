모든 Webza 요금제에서 자신의 Supabase 프로젝트를 연결하면 생성된 앱에 데이터베이스 기능을 추가할 수 있습니다. 앱은 관계형 Postgres 테이블, 인증, 저장소, 행 수준 보안(RLS)을 갖게 됩니다. AI는 빌드 과정에서 테이블과 인증 흐름을 자동으로 정의합니다.

<Note>
  데이터베이스 연결은 WordPress 또는 Shopify 테마 프로젝트에서 사용할 수 없습니다.
</Note>

## 데이터베이스는 내 것입니다

Webza는 자신의 데이터베이스를 가져오는(BYOD) 모델을 사용합니다. 사용자가 Supabase 프로젝트를 제공하면, 생성된 앱은 `@supabase/supabase-js` 클라이언트를 통해 이와 통신합니다. Webza는 데이터베이스를 생성, 호스팅, 소유하거나 비용을 청구하지 않습니다.

- 자신의 Supabase 연결 라이브러리를 보관하고 각 프로젝트에 하나를 연결합니다.
- Webza는 각 프로젝트를 위해 데이터베이스 내에 전용 스키마를 생성하고 테이블을 구축합니다.
- Webza는 프로젝트를 삭제하더라도 데이터를 절대 삭제하지 않습니다.

## 작동 방식

<Steps>
  <Step title="연결 추가">
    사이드바의 **데이터베이스** 페이지에서 하나 이상의 Supabase 연결을 저장하세요.
  </Step>
  <Step title="프로젝트에 선택">
    프로젝트를 생성할 때 **데이터베이스** 선택기에서 연결을 선택하세요. 첫 빌드부터 연결됩니다.
  </Step>
  <Step title="AI가 빌드하도록 하기">
    Webza는 Supabase 프로젝트 내에 RLS가 활성화된 Postgres 스키마를 생성합니다. AI는 앱을 빌드하면서 테이블을 추가합니다.
  </Step>
</Steps>

## Supabase 연결 추가하기

사이드바에서 **데이터베이스**를 열고 **연결 추가**를 클릭하세요. 각 연결은 하나의 Supabase 프로젝트에 대한 이름과 접근 권한을 저장합니다. 최대 20개의 연결을 저장하고 프로젝트 간에 재사용할 수 있습니다.

표시되는 방법은 계정에 활성화된 기능에 따라 다릅니다. 사용 가능한 방법이 하나뿐이라면 **연결 추가**가 해당 방법을 바로 엽니다.

| 방법 | 필요한 것 | 접근 범위 |
| --- | --- | --- |
| **Supabase로 연결** | Supabase 로그인 정보 | 승인한 조직의 모든 프로젝트 |
| **액세스 토큰** | 프로젝트 범위 액세스 토큰 | 선택한 프로젝트만 |
| **수동** | Session pooler URI, 데이터베이스 비밀번호, 공개 키 | 해당 프로젝트만 |

<Tabs>
  <Tab title="Supabase로 연결">
    <Steps>
      <Step title="로그인 시작">
        **데이터베이스** 페이지에서 **연결 추가**를 클릭하고 **Supabase로 연결**을 선택하세요.
      </Step>
      <Step title="Webza 승인">
        Supabase 동의 화면에서 권한을 검토하고 프로젝트가 있는 조직을 승인하세요. Supabase는 쓰기 권한에 읽기가 포함되므로 **Database**를 읽기 및 쓰기로 표시합니다.
      </Step>
      <Step title="프로젝트 선택">
        활성 프로젝트를 선택하고 연결을 저장하세요.
      </Step>
    </Steps>

    <Warning>
      Supabase는 조직 단위로 접근 권한을 부여하므로, 선택한 조직의 모든 프로젝트를 승인하게 됩니다. Webza는 선택한 프로젝트에서만 작동합니다. 단일 프로젝트로 접근을 제한하려면 액세스 토큰을 사용하세요.
    </Warning>

    OAuth 세션은 자동으로 갱신되므로, 접근 권한이 유지되는 한 다시 로그인할 필요가 없습니다.
  </Tab>
  <Tab title="액세스 토큰">
    <Steps>
      <Step title="Supabase에서 토큰 생성">
        Supabase에서 **Account → Access Tokens**을 열고 토큰을 생성하세요. **Project access**를 선택하고 연결할 프로젝트만 지정한 뒤 만료 기한을 설정하세요.
      </Step>
      <Step title="권한 설정">
        다음 권한을 정확히 부여하세요.

        - **Database**: Read-write
        - **API Keys**: Read
        - **Projects** (account-wide): Read
      </Step>
      <Step title="Webza에 저장">
        **데이터베이스 → 연결 추가 → 액세스 토큰**을 열고 토큰을 붙여넣은 뒤 **계속**을 클릭하세요. 프로젝트를 선택하고 저장하면, Webza가 프로젝트 URL과 공개 키를 자동으로 가져옵니다.
      </Step>
    </Steps>

    <Note>
      `sbp_fc`로 시작하는 프로젝트 범위 토큰만 허용됩니다. 레거시 전체 계정 토큰은 거부됩니다. 일시 중지되거나 사용 불가능한 프로젝트는 선택할 수 없습니다.
    </Note>
  </Tab>
  <Tab title="수동">
    <Steps>
      <Step title="Supabase 프로젝트 생성">
        [Supabase Dashboard](https://supabase.com/dashboard)에 로그인하고 프로젝트를 생성하세요. 무료 요금제로도 시작할 수 있습니다.
      </Step>
      <Step title="공개 키 복사">
        **Project Settings → API Keys**를 열고 공개 키(`sb_publishable_…`)를 복사하세요. 이전 프로젝트의 경우 **Project Settings → API** 아래에 레거시 `anon` 키가 표시될 수 있으며, 이것도 작동합니다.
      </Step>
      <Step title="Session pooler URI 복사">
        Supabase 프로젝트 상단의 **Connect**를 클릭하고 **Session pooler**와 **URI** 유형을 선택한 뒤 연결 문자열을 복사하세요. 문자열 내 `[YOUR-PASSWORD]`는 그대로 두세요.

        ```text
        postgresql://postgres.abcdefgh:[YOUR-PASSWORD]@aws-0-ap-southeast-1.pooler.supabase.com:5432/postgres
        ```
      </Step>
      <Step title="Webza에 저장">
        **데이터베이스 → 연결 추가 → 수동**을 열고 다음을 입력하세요.

        - **연결 이름**: 인식할 수 있는 이름.
        - **연결 문자열**: Session pooler URI. `postgres://` 또는 `postgresql://`로 시작해야 합니다. `psql` 명령은 붙여넣지 마세요.
        - **데이터베이스 비밀번호**: 데이터베이스 비밀번호. Webza가 이를 인코딩하여 `[YOUR-PASSWORD]` 자리에 삽입합니다.
        - **공개 키**: 복사한 키.

        **Supabase URL**은 연결 문자열에서 자동으로 채워집니다. `https://`로 시작해야 합니다.
      </Step>
      <Step title="연결 테스트">
        **연결 테스트**를 클릭하세요. 데이터베이스 접근과 공개 키를 별도로 확인합니다.
      </Step>
    </Steps>

    나중에 수동 연결을 편집할 때, 연결 문자열이나 공개 키를 비워두면 저장된 값이 유지됩니다.
  </Tab>
</Tabs>

### 이메일 확인 끄기

생성된 앱에서 가입이 즉시 작동하도록 하려면, Supabase에서 이메일 확인을 끄세요. **Authentication → Sign In / Providers → Email**으로 이동하여 **Confirm email**을 끄고 저장하세요.

<Warning>
  Supabase 프로젝트에 SMTP를 구성하지 않은 상태에서 확인을 켜두면, 가입이 활성 세션을 반환하지 않고 로그인이 조용히 실패합니다.
</Warning>

## 프로젝트에 데이터베이스 연결하기

생성 페이지에서 **사용자 지정** 팝오버를 열고 **데이터베이스** 선택기에서 연결을 선택하세요. 선택기는 최소 하나의 연결을 저장한 후에만 표시됩니다. 정적 사이트의 경우 **데이터베이스 없음**으로 두세요.

나중에 데이터베이스를 연결, 전환 또는 분리하려면 프로젝트의 **설정 → 데이터베이스**로 이동하세요.

- 연결을 전환해도 스키마는 삭제되지 않습니다. 이전 스키마는 생성된 데이터베이스에 그대로 남습니다.
- 언제든지 데이터베이스를 분리할 수 있습니다.
- 프로젝트를 복제해도 데이터베이스 연결은 복사되지 않습니다.

## 테이블 접근 모드

AI가 생성하는 각 테이블은 세 가지 접근 모드 중 하나를 사용합니다. 모드는 Webza가 작성할 RLS 정책을 결정하므로, 데이터베이스 기반 앱에서 가장 중요한 보안 선택입니다.

| 모드 | 쓰기 가능자 | 읽기 가능자 | 사용처 |
| --- | --- | --- | --- |
| `public` | 누구나 | 누구나 | 방명록, 댓글, 공개 리뷰 |
| `private` | 로그인한 행 소유자 | 로그인한 행 소유자 | 할 일, 노트, 프로필, 기타 사용자별 데이터 |
| `submit` | 누구나 | 앱에서는 아무도 | 문의 양식, 문의, 대기 목록, 뉴스레터 구독 |

<Warning>
  폼 제출에는 절대 `public`을 사용하지 마세요. 공개 키는 의도적으로 사이트의 JavaScript에 포함되므로, 누구든 `public` 테이블의 모든 행을 읽고 삭제할 수 있습니다. 방문자가 비공개로 보내는 모든 것에는 `submit`을 사용하세요.
</Warning>

`submit` 테이블은 방문자가 행을 삽입할 수 있지만, 브라우저에서는 읽기, 업데이트, 삭제가 불가능합니다. 앱은 폼을 전송하고 성공 메시지를 표시합니다. 제출 내용은 Supabase 대시보드에서 확인하세요.

프롬프트에서 AI에게 사용할 모드를 알려줄 수 있습니다. 예: "문의 폼 메시지를 submit 테이블에 저장해줘."

### 테이블 모드 변경하기

AI에게 기존 테이블을 다른 모드로 재정의하도록 요청하세요. Webza는 테이블의 정책을 다시 작성하고 데이터는 유지합니다.

<Warning>
  `public` 또는 `submit` 테이블을 `private`로 전환하면 기존 행이 숨겨집니다. 해당 행에는 소유자가 없으므로 어떤 사용자도 앱에서 볼 수 없습니다. 데이터는 Supabase 대시보드에 그대로 있습니다. 행이 중요하다면 전환 전에 소유자를 할당하거나 내보내세요.
</Warning>

### 관리되는 열

모든 테이블에는 자동으로 `id`와 `created_at` 열이 추가됩니다. `private` 테이블에는 `user_id` 열도 추가됩니다. 이 열들은 직접 정의하지 마세요.

## 앱이 받는 것

- **관계형 Postgres**: 실제 테이블, 외래 키, SQL 쿼리.
- **행 수준 보안**: Postgres가 강제하는 행별 접근 정책.
- **인증 및 저장소**: 앱은 Supabase Auth(이메일 및 비밀번호 또는 제공업체 로그인)와 Storage 버킷을 사용할 수 있습니다. Auth 제공업체와 Storage 버킷은 자신의 Supabase 대시보드에서 구성하세요.

각 프로젝트는 `proj_` 뒤에 하이픈 없는 프로젝트 ID가 붙은 이름의 자체 스키마를 받습니다. 예를 들어 ID가 `3f0c1a2b-…`인 프로젝트는 `proj_3f0c1a2b…`를 사용합니다.

생성된 앱은 프로젝트 URL, 공개 키, 스키마 이름만 받습니다. 액세스 토큰과 연결 문자열은 암호화되며 브라우저에 전달되지 않습니다.

<Info>
  프로젝트를 삭제하거나, 데이터베이스를 분리하거나, 연결을 전환해도 프로젝트의 스키마나 데이터는 절대 삭제되지 않습니다. 공간을 확보하려면 Supabase 대시보드에서 `proj_…` 스키마를 직접 제거하세요.
</Info>

## 접근 권한 관리

- 하나의 액세스 토큰이나 Supabase 로그인으로 여러 연결을 지원할 수 있습니다. Supabase 로그인을 재연결하면 해당 로그인으로 만든 모든 연결이 복구됩니다.
- 교체한 액세스 토큰은 편집 중인 연결에만 적용됩니다. 이전 토큰을 사용한 각 연결에 새 토큰을 붙여넣으세요.
- 토큰과 로그인은 최대 10개까지 저장할 수 있습니다.

Webza에서 연결을 삭제해도 Supabase의 접근 권한은 취소되지 않습니다. 접근 권한을 취소하려면 다음을 수행하세요.

- **Supabase로 연결**: 조직의 **Settings → OAuth Apps → Authorized apps**에서 Webza를 제거하세요.
- **액세스 토큰**: **Account → Access Tokens**에서 토큰을 삭제하세요.

접근 권한이 취소되거나 토큰이 만료되면, 연결은 **데이터베이스** 페이지에 **재연결**을 표시하고 빌드에서 접근 권한이 취소되었다고 보고합니다. 재연결하면 연결이 그 자리에서 복구되므로, 연결된 프로젝트의 스키마는 유지됩니다.

## 문제 해결

<AccordionGroup>
  <Accordion title="연결 테스트 실패">
    - 수동 연결의 경우 **Connect**의 Session pooler URI를 사용하고 `[YOUR-PASSWORD]`는 그대로 두며, **데이터베이스 비밀번호** 필드에 비밀번호를 입력하세요.
    - 공개 키가 거부되면 동일한 Supabase 프로젝트에서 다시 복사하세요.
    - Supabase 프로젝트가 활성 상태이며 일시 중지되지 않았는지 확인하세요.
    - 연결에 **재연결**이 표시되면 토큰을 교체하거나 Webza를 다시 승인하세요.
  </Accordion>

  <Accordion title="앱이 폼 제출을 표시하지 않습니다">
    `submit` 테이블의 경우 이는 예상된 동작입니다. 브라우저에서는 쓰기 전용이므로 제출 내용이 앱에 표시되지 않습니다. Supabase 대시보드에서 확인하세요. 앱이 제출 내용을 표시하는 것처럼 보인다면, 샘플 플레이스홀더 행을 보여주는 것입니다.
  </Accordion>

  <Accordion title="앱이 데이터를 읽을 수 없습니다">
    - 프로젝트의 **설정 → 데이터베이스**에 연결이 연결되어 있는지 확인하세요.
    - 공개 키가 **연결 테스트**를 통과하는지 확인하세요.
    - 테이블의 접근 모드를 확인하세요. 정책이 허용하지 않으면 RLS가 접근을 거부합니다.
  </Accordion>

  <Accordion title="가입은 되지만 로그인이 실패합니다">
    Supabase 프로젝트에서 **Confirm email**을 끄거나 SMTP를 구성하세요. [이메일 확인 끄기](#이메일-확인-끄기)를 참조하세요.
  </Accordion>

  <Accordion title="Supabase에서 스키마 변경이 되돌려졌습니다">
    Webza는 Supabase API에 노출할 스키마를 관리합니다. Supabase 대시보드에서 **Exposed schemas**를 편집하면 Webza 설정에 의해 덮어쓰입니다.
  </Accordion>
</AccordionGroup>
