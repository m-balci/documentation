모든 Webza 요금제에서 GitHub 계정을 연결할 수 있습니다. 연결하면 매 빌드 성공 후 프로젝트 소스 코드가 내 계정의 저장소에 푸시됩니다. 코드는 내가 관리하며, Webza를 떠나지 않고도 최신 상태를 유지할 수 있습니다.

<Note>
  GitHub 통합은 WordPress 또는 Shopify 테마 프로젝트에서 사용할 수 없습니다.
</Note>

## 작동 방식

<Steps>
  <Step title="GitHub 계정 연결">
    Webza GitHub 앱을 내 계정이나 조직에 설치하고 Webza에서 연결하세요.
  </Step>
  <Step title="프로젝트에 계정 선택">
    프로젝트를 생성할 때 GitHub 연결을 선택하면, Webza가 새로운 비공개 저장소를 만들어 줍니다.
  </Step>
  <Step title="빌드">
    매 빌드 성공 후 AI가 생성된 커밋 메시지와 함께 프로젝트 소스를 푸시합니다.
  </Step>
</Steps>

<Info>
  Webza는 내 저장소에만 푸시합니다. 저장소 내용을 클론, 풀, 빌드하지 않습니다. 저장소는 출력이지 입력이 아닙니다.
</Info>

## GitHub 계정 연결하기

<Steps>
  <Step title="사이드바에서 GitHub 열기">
    사이드바에서 **GitHub**를 클릭한 뒤 **GitHub 연결**을 클릭하세요.
  </Step>
  <Step title="Webza 앱 설치">
    GitHub가 Webza 앱 설치를 요청합니다. 모든 저장소 또는 선택한 저장소만 접근할지 선택하세요.
  </Step>
  <Step title="Webza로 돌아가기">
    연결이 저장된 상태로 Webza로 다시 이동됩니다.
  </Step>
</Steps>

개인 계정이나 조직을 여러 개 연결할 수 있으며, 최대 20개의 연결이 가능합니다.

## 프로젝트에 저장소 연결하기

프로젝트를 생성할 때 대시보드 프롬프트 상자의 **사용자 지정**을 클릭한 뒤 **통합**을 선택하고 GitHub 연결을 고르세요. Webza가 저장소를 자동으로 생성합니다.

기존 프로젝트의 경우 **설정 → 일반**으로 이동하여 **GitHub 저장소** 섹션을 찾으세요. 여기에서 다음을 할 수 있습니다.

- 새로운 비공개 저장소 만들기
- 소유자와 저장소 이름을 입력하여 기존 저장소 연결하기
- 다른 저장소로 전환하거나 연결 해제하기
- **자동 푸시** 켜기 또는 끄기

<Warning>
  기존 저장소는 비어 있어야 합니다. 이미 코드가 포함된 저장소를 연결하면 "That repository already contains code" 오류가 발생합니다. Webza는 볼 수 없는 작업을 덮어쓸 수 없기 때문입니다.
</Warning>

프로젝트를 복제해도 GitHub 연결은 복사되지 않습니다. 여러 프로젝트가 하나의 저장소를 공유하면 한 프로젝트가 다른 프로젝트의 파일을 덮어쓸 수 있으므로, 각 프로젝트는 별도의 연결이 필요합니다.

## 요청 시 푸시

**자동 푸시**를 끈다고 해서 수동으로 푸시해야 하는 것은 아닙니다. 프로젝트 채팅에서 AI에게 "이것을 GitHub에 푸시해줘"라고 요청하면, 토글 상태와 상관없이 일회성 푸시를 실행합니다.

<Tip>
  각 커밋이 반영되기 전에 변경 사항을 검토하려면 자동 푸시를 끄고, 준비가 되면 AI에게 푸시를 요청하세요.
</Tip>

## 푸시되는 내용

Webza는 작업 공간 전체가 아닌, 개발자가 읽고 싶어할 프로젝트 소스를 푸시합니다. 의존성, 빌드 출력, 자격 증명으로 보이는 모든 것은 제외되므로, 비밀 정보가 저장소에 노출되지 않습니다.

## Webza 외부에서 저장소 편집하기

푸시는 강제로 실행되지 않습니다. 누군가 Webza 외부에서 저장소에 커밋하면, 다음 푸시는 해당 변경 사항을 보호하기 위해 건너뜁니다.

<Warning>
  이후 저장소와 Webza 프로젝트는 동기화되지 않은 상태가 됩니다. Webza는 외부 변경 사항을 프로젝트에 병합하지 않으며, 해당 브랜치로의 추가 푸시도 건너뜁니다.
</Warning>

## 보안

- GitHub 토큰은 암호화되어 저장되며 어떤 API 응답에도 포함되지 않습니다.
- 각 푸시는 1시간 동안만 유효하고 해당 저장소에서만 작동하는 새로운 토큰을 사용합니다.

## 연결 상태

**GitHub** 페이지의 각 연결은 다음 세 가지 상태 중 하나를 표시합니다.

| 상태 | 의미 | 조치 |
| --- | --- | --- |
| **활성** | 정상 작동 중 | 아무것도 할 필요 없음 |
| **재연결 필요** | Webza의 인증은 제거했지만 앱은 설치된 상태입니다. 푸시는 여전히 작동하지만, 새 프로젝트에 저장소를 연결할 수 없습니다. | **재연결** 클릭 |
| **취소됨** | 앱이 제거되거나 일시 중지되었습니다. 아무것도 작동하지 않습니다. | **재연결** 클릭 |

## 접근 권한 제거

프로젝트에서 저장소 연결을 해제하려면 **설정 → 일반**으로 이동하세요. GitHub 계정에서는 아무것도 삭제되지 않습니다.

Webza의 접근 권한을 완전히 취소하려면 GitHub 설정에서 Webza 앱을 제거하세요. 저장소와 그 내용은 계정에 그대로 남습니다.

## 문제 해결

<AccordionGroup>
  <Accordion title="푸시가 중단되었습니다">
    - 누군가 Webza 외부에서 저장소에 커밋했을 수 있습니다. 해당 변경 사항을 보호하기 위해 푸시가 건너뜁니다.
    - Webza 앱이 GitHub 계정에서 제거되었을 수 있습니다. **GitHub** 페이지에서 연결 상태를 확인하고 재연결하세요.
    - 프로젝트의 **설정 → 일반**에서 **자동 푸시**가 켜져 있는지 확인하세요.
  </Accordion>

  <Accordion title="기존 저장소를 연결할 수 없습니다">
    저장소는 비어 있어야 합니다. GitHub에서 새로운 빈 저장소를 만들거나, Webza가 생성하도록 하세요.
  </Accordion>

  <Accordion title="Webza가 내 저장소를 볼 수 없습니다">
    선택한 저장소에만 접근 권한을 부여한 경우, GitHub 설정에서 Webza 앱의 접근 목록에 해당 저장소를 추가하세요.
  </Accordion>

  <Accordion title="조직 연결이 작동하지 않습니다">
    조직 연결의 인증이 제거된 경우, Webza가 즉시 감지하지 못할 수 있습니다. 다음에 저장소를 연결하려 할 때 알게 됩니다. **GitHub** 페이지에서 재연결하세요.
  </Accordion>
</AccordionGroup>
